# syntax_tree

`string *syntax_tree(string name, string source)`

Return diagnostic lines describing the checked frontend tree of a complete LPC
program supplied as text. The program is preprocessed and semantically checked,
including its includes, inherits and simulated efuns. Syntax, type and name errors
propagate through `catch`; warnings use the normal warning handler.

`name` identifies the source for diagnostics and relative include/inherit paths.
It resolves against the calling object's directory; a trailing `.c` is optional.
Clone names and paths outside the library are rejected. The named directory need
not exist. Both arguments are required strings.

The master must allow `valid_write` followed by `valid_load` for the canonical
source name ending in `.c`. Both receive the operation `"syntax_tree"`, the
executing caller and its defining program. These checks authorize supplying code
under that identity. Includes, inherits and explicit efun calls retain their
normal compiler authorization. No new apply is used.

Analysis joins the calling transaction and sees pending source-file changes and
its current simulated-efun binding. The source identity can already belong to a
loaded object or a file: neither is replaced, read as root source or modified.
The operation creates no object, invokes no LPC initializer or inspected function,
and writes no source or dump file. Permission and warning hooks run normally and
can have their usual effects. Inherited programs are checked and generated by
the frontend, without being loaded or initialized.

The tree contains the root's declarations, functions, statements and expressions,
including private/protected code and generated closure/capture details. Expanded
includes are part of this tree; inherits appear as declarations rather than
flattened parent bodies. Constant folding and frontend normalization have already
happened. Prototypes and other syntax discarded by the parser are not reconstructed.
This is a diagnostic view, not a reversible source representation, stable data
schema or bytecode listing. Its format may change with the compiler.

Each returned string is one line without a newline. Literal strings are quoted
and escaped, including embedded newlines, NUL and terminal controls; controls in
source/type metadata are escaped too. Rendering
rejects a line exceeding 8,192 UTF-8 bytes, more than 65,536 lines, or more than
4 MiB including indentation and one newline per line. It returns no partial result
on error and yields periodically for task cancellation. Larger successful trees
can exceed one LPC string's limit; print lines separately. Returned arrays are fresh.

```c
string *lines = syntax_tree("/wizard/inspect",
    "int add(int left, int right) { return left + right; }");
foreach (string line in lines) {
    write(line);
    write("\n");
}
```
